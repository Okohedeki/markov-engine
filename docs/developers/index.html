Submit once

One case. Stable state.

Use an idempotency key when retrying submission. Poll the job or consume its webhook, then retrieve the shared research case and artifact.

REQUESTPOST /v1/jobs
curl -X POST https://your-markov-host/v1/jobs \
  -H "X-Markov-Key: $MARKOV_API_KEY" \
  -H "Idempotency-Key: housing-rates-2026-08" \
  -H "Content-Type: application/json" \
  -d '{
    "mode": "research",
    "review_level": "instant",
    "inputs": [{
      "type": "url",
      "value": "https://example.org/source"
    }],
    "constraints": {
      "focus": "Which claims survive independent checking?"
    },
    "webhook_url": "https://agent.example/hooks/markov"
  }'

The contract

More than an endpoint.

The API exposes the work around the artifact so another system can reason about it instead of treating generated prose as ground truth.

STATE

Jobs and events

Queued, running, awaiting review, complete, or failed—with meaningful stages.

EVIDENCE

Claims and passages

Stance, strength, rationale, source quality, and exact locators remain structured.

OUTPUT

Artifacts and exports

Briefs, reports, and scripts can be fetched as structured data or exported documents.

Designed for retries, ownership, and continuation.

Operational surface

  • Bearer or X-Markov-Key authentication
  • Owner-scoped jobs and cases
  • Idempotent job creation
  • Webhook delivery with polling fallback

Continuation surface

  • Convert one case into another format
  • Deepen one unresolved claim
  • Revise script sections without inventing evidence IDs
  • Export Markdown, HTML, or JSON
